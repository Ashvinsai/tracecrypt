# Project package — what's here and how to run it

Project source **plus** the demo data the investigator console needs.
Excludes installed dependencies and caches, which the setup steps restore.

## What was excluded, and why

| Excluded | Reason |
|---|---|
| `api/.venv/` | 489 MB of installed Python packages. Reinstalled by `uv sync`. |
| `api/.mypy_cache/`, `.ruff_cache/`, `.pytest_cache/` | Regenerated by tooling. |
| `frontend/node_modules/` | 90 MB of installed JS packages. Reinstalled by `npm ci`. |
| `.git/` | Local history; not needed to run the demo. |
| **`api/.env`** | **Contains a live `CFA_TRON_API_KEY`. Deliberately not included.** |
| `okx.com/` | 37 MB preserved OKX proof-of-reserves archive. See note below. |

| `.commandcode/`, `graphify-out/` | Local agent/tooling scratch. |
| `*.pptx.bak*`, `docs.zip` | Stale backups. |

`api/.env.example` **is** included. I verified by searching the finished archive with
the real key value that the key does **not** appear anywhere in it.

## Setup

One command prepares everything the demo needs (Python deps, frontend deps,
the investigator workspace build, and the synthetic demo artifacts). It is the
only step that may need network access.

```bash
make demo-prepare
```

That is equivalent to:

```bash
cd api
uv sync --all-groups                       # installs from the pinned api/uv.lock
cp .env.example .env                       # optional; defaults work, set CFA_TRON_API_KEY for live
cd ../frontend && npm ci                   # installs from the committed package-lock.json
npm run build                              # builds the /investigator workspace into frontend/dist
cd ../api && uv run alembic upgrade head   # creates the local SQLite case DB
CFA_DATA_MODE=SYNTHETIC uv run python ../scripts/trace_demo.py   # writes the synthetic demo artifacts
CFA_DATA_MODE=SYNTHETIC uv run python ../scripts/seed_demo.py    # loads the synthetic demo case + login
```

## Run the demo

```bash
make demo        # http://localhost:8010/investigator
```

`make demo` serves the already-prepared workspace. It never installs
dependencies: if `frontend/dist` is missing it either rebuilds from an existing
`frontend/node_modules` (no network) or stops with instructions to run
`make demo-prepare`. `/investigator` is never silently hidden.

| URL | What it is |
|---|---|
| `/investigator` | **The investigator workspace** (React) — the main demo surface |
| `/` | Overview and what the system will not claim |
| `/console` | Legacy server-rendered investigator console over saved results |
| `/graph?preset=recorded-okx-direct` | Fund-flow graph, real recorded data |
| `/dashboard` | Capability matrix, bundle integrity, ML readiness |

Read `docs/DEMO_RUNBOOK.md` first — a timed 2–3 minute judge script with the exact
numbers to point at and a no-internet fallback.

Two presets ship: `recorded-okx-direct` (**real** TronGrid run recorded 2026-09-26,
terminating at an OKX address) and `synthetic-multihop` (fictional, 8 transfers,
4 branch endings, 2 unresolved — use it to show uncertainty handling).

## Capability reporting

`/api/v1/meta` and the `/dashboard` matrix now derive from one shared evaluator,
`api/app/services/operational_status.py`. The requirements matrix in
`docs/REQUIREMENTS_MATRIX.md` uses DONE / PARTIAL / NOT BUILT / NOT CONFIGURED /
BLOCKED, and distinguishes **implemented** from **configured** from
**live-verified**.

Two things it deliberately does *not* claim:

- A recorded successful LIVE run is reported as **historical** evidence. It does
  not make the *current* deployment live-verified.
- OKX proof-of-reserves claims stay scoped to the snapshot instant they prove.
  Their `valid_from`/`valid_to` were **not** widened to make traces terminate.

## Known gaps, in the order I'd close them

1. **Only one real trace exists, and it is 1 hop** (seed → OKX, direct). A real
   4–5 hop trace terminating at a VASP is the single highest-value addition for
   the problem statement.
2. **The OKX PoR archive is not in git** (by the existing `okx.com/` rule).
   Acceptance tests `J01`–`J08` assert it exists and matches its hash; they pass
   here but will fail on a clean clone.
3. **Multi-chain is `PARTIAL`, bridge/cross-chain tracing is not built.** A
   generic EVM JSON-RPC adapter (`api/app/adapters/evm.py`) has a bounded, real
   Ethereum Mainnet ERC-20 LIVE validation on file and replayed offline through
   the same adapter with zero network calls and matching results
   (`var/live-validation/20260926-ethereum-usdt-live-001/`, replay
   `.../20260926-ethereum-usdt-replay-001/`) -- see `docs/REQUIREMENTS_MATRIX.md`
   R13. This is one historical validation, not a continuously live-verified
   deployment. BNB Smart Chain (chain id 56) runs on the same adapter as a
   second registry entry with its own `CFA_BSC_RPC_URL`. It has one bounded
   historical LIVE validation (`var/live-validation/20260926-bsc-usdt-live-002/`)
   and a zero-network replay (`.../20260926-bsc-usdt-replay-001/`). The BSC
   token is a technical validation token whose issuer is not established
   (`docs/BSC_TOKEN_PROVENANCE.md`). Native ETH/BNB value transfers, other EVM
   chains, and a verified cross-chain protocol remain a separate increment. Bounded, anchor-centered
   TRON neighborhood discovery is `PARTIAL`: it emits review-only candidate
   observations, not wallet-ownership
   clusters.
4. **ML is synthetic-only** — `NOT_READY_FOR_REAL_EVALUATION`, 2 real wallets, both
   confounders. This is blocked on labeled data, not code. Do not fake it.
5. **NCRP/SAHYOG are not built and not configured** by policy. No public API
   exists; the local mock queue is a separate, clearly-labelled component.
6. **`frontend/` is a one-page status shell.** The product UI is the
   server-rendered console.

## Two evidence-integrity notes

- `okx.com/por_csv_2026081100_V6.zip` is a third-party exchange disclosure
  preserved unmodified as provenance. It is included here so the evidence chain
  is complete, but if this archive goes somewhere untrusted, reconsider that file.
- Manifest hashes prove files have **not changed**. They do not prove an
  attribution is correct or admissible. Every bundle in this repo says so.

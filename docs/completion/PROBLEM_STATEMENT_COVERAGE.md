# Problem statement → implementation coverage

## Release conclusion

v2 completes an end-to-end **local investigative prototype workflow**: intake → persistent job → bounded verified trace → evidence-qualified nearest receiving VASP or explicit unresolved result → dashboard signal → saved evidence export. It does **not** complete an operational national-scale service merely by implementing these paths. The table separates source implementation, offline verification, access prerequisites and scope boundaries.

| Requested requirement | Implementation and evidence | Remaining qualification |
|---|---|---|
| Ingest complaint wallet addresses | Strict application-owned schema, UI and scoped bearer endpoint; idempotent reference/hash handling, up to 20 wallets, exact-network address validation. End-to-end API tests. | An authorized agency gateway must map its actual approved schema and identity/consent controls. No public official schema was assumed. |
| Automatically trace suspects | Durable jobs execute chronological, token-specific tracing; incident start/cutoff, successful execution and confirmed continuation gates. Synthetic worker/API tests. | Supported configured providers/tokens only; real-provider reachability, quotas and finality affect results. |
| Identify nearest receiving exchange/VASP | First accepted receiving service per verified branch, actual observed transfer-hop ranking and tied nearest candidates. Evidence references and limitations are retained. | Nearest in the observed bounded graph, not globally nearest or proof of control over the sender. No guaranteed match without good labels. |
| Distinguish direct deposits | Reports whether the service was reached directly or through intermediaries; deposit role only from accepted role evidence. | A service hot-wallet endpoint is not automatically a customer deposit address. No account-holder KYC identity is inferred. |
| Exchange clustering | Grouping of accepted same-entity service-control evidence; original candidate review and independent-evidence policies retained; label conflicts block arbitrary attribution. | Broad automatic exchange-cluster discovery is not validated. Behavioral similarity is a lead, not proof of a common controller. |
| Detect intermediary/laundering patterns | Exact-transfer supporting references for fan-in/out, rapid/repeated forwarding, peeling-like splits and bounded cyclic topology. Cross-case network/mode separation. | Indicates behavior compatible with multiple explanations; not a finding of laundering, guilt or burner-wallet ownership. |
| Multiple ecosystems | Existing TRON TRC20 and Ethereum/BSC/Base ERC20 transfer adapters retained, with separate RPC settings and chain checks. | Not Bitcoin, Solana, native/internal transfers, all tokens, universal DeFi decoding or privacy-chain tracing. Some adapter modules could not run without dependencies. |
| Cross-chain analytics | New checked Ethereum→Base USDC CCTP V2 API, raw evidence/hash storage, source/destination reconciliation and optional explicit recipient-continuation job. Recorded-fixture and mocked-HTTP negative/positive tests. | No new live RPC execution during this build. Single-message route only. No arbitrary bridge correlation, swap amount allocation, mixer deanonymization or independent attestation signature verification. |
| Real-time operation | Persistent worker polls at configurable intervals; dashboard refresh, deduplicated watches and review signals; durations measured from actual stored jobs. | Near-real-time polling, not guaranteed instantaneous or mempool coverage. No measured production SLA, throughput claim or always-on hosted service. |
| Automated alerts | Durable attributed/unresolved/coverage-gap/retry signals with acknowledgement, plus retained watch alerts. | These are investigator signals. No automatic freezing, outbound government notices or verified external delivery. |
| Risk and AI/ML | Evidence-linked deterministic priority rules plus actual optional held-out IsolationForest anomaly ranking; optional original CLM shadow router retained. | No labelled operational fraud dataset; fraud precision/recall/calibration not established. ML cannot upgrade ownership labels or initiate enforcement. |
| LEA dashboard | One local workspace for intake/jobs/graphs/cases/monitoring/correlations/CCTP/decision support; organization-aware APIs. | Basic authorization, not a completed government SSO/RBAC/accreditation deployment. |
| Standard investigation reports | Saved JSON/HTML/PDF/CSV, exact transfer identifiers, provenance, scope/limitations, SHA-256 manifest and linked checked bridge evidence where present. | Standardized application format, not certification of a court-specific evidentiary form. Hashes alone do not authenticate external sources or prove legal admissibility. |
| APIs and scalable indexing | OpenAPI/JSON schema, persistent queue, indexed exact saved-run observations and cursor retrieval. Conditional PostgreSQL queue claims use SKIP LOCKED. | No whole-chain index or PostgreSQL load/failover validation performed. Local SQLite is single-worker prototype storage. |
| NCRP and SAHYOG integration | Scoped authenticated interoperability endpoint, local credential administration and explicit connector-not-configured state. | Official authorization, schemas, onboarding, approvals and actual platform transport remain external. No claim of an existing production connection. |
| Coordination with VASPs / freezing | Evidence-qualified information/preservation/restriction request drafts and investigator handoff exports. | Draft-only. A competent authorized agency/VASP must review and carry out any actual request. The application cannot unilaterally freeze exchange assets. |
| Faster response / recovery | Removes manual local intake-to-trace orchestration and preserves structured evidence. | Actual time savings, recovery rates and production outcomes need prospective operational evaluation. None are fabricated. |

## What must be done before using real complaints

Obtain authorized provider access, independently reviewed current service labels and token metadata; configure a separate LIVE environment; complete official agency/VASP integration and legal review; perform threat modelling, role/permission review, backups/retention, incident-response and availability work; validate live chain coverage and run the full dependency-complete suite. Deploy and load-test an appropriate database/indexing infrastructure before multi-agency or large-volume operation.

The strongest implementation choice is **explicit uncertainty**. A provider timeout, conflicting owner label, unidentified service or unsupported bridge remains unresolved. No UI status or synthetic fixture is used to manufacture successful attribution.
